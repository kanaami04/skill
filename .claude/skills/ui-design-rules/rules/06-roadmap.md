# 開発方針

## Phase 1(完了)

Claude CodeのSkill、Markdown、テンプレートだけでルールを検証する。

- 独自のAI APIや外部AIサービスには依存しない。
- 巨大なデザインエディタを作らない。まず再現性のあるワークフローを確立する。
- 最初の実験: dashboard-001(Baseline が勝った。`experiments/dashboard-001/experiment-log.md` §8)。

## Phase 2(現在)

複数プロジェクトで実験し、効果のあるルールを改善・整理する。

- 効かなかったルール、効いたルールを実験ログから拾う。
- ルールの追加より、削除と整理を優先する。

## Phase 3

効果が確認できたワークフローのうち、手作業で不便な部分をSaaS化する。

- デザイン案の管理
- プレビュー
- 比較
- 選定
- 仕様出力

## 原則

- 独自のAI APIへの依存を避ける。Claude Codeの利用環境に必要な認証や利用条件は尊重する。
- SaaS化は急がない。Phase 1で再現性が確認できてから検討する。

## 改訂履歴

### v2(2026-10-15)

根拠: `experiments/dashboard-001/experiment-log.md` §8、`research/2026-10-15-ui-fundamentals.md`。

- 3案の軸を「見た目の型」(Clarity First / Editorial Character / Operational Density)から、「見せる UI と実務の UI の配分」(Practical / Balanced / Presentable)に変えた。Editorial が記事風に流れ、Clarity が Baseline と同じ骨格になったため。
- 3案の前に「共通の土台」(画面の種類と慣習、焦点、囲む単位、強調の段階)を決める Step を追加した。
- 原則に「画面の種類の慣習を守る」「焦点を1つ」「囲みは1段」を追加した。修正の過程で囲みをゼロにし、管理画面に見えなくなったため。
- アンチパターンに、実際に出た AI典型(左の色線、淡いバッジ、強調の入れ子、動かない飾りなど)と、数える方法・上限を追加した。抽象的な原則だけでは止まらなかったため。
- 採用案の修正で、原案の方向性に縛られないことを明記した(Step 7)。案Cが原案に引っ張られ、修正しても違いが出なかったため。
- 推奨の判断順を明記し、「仕様にしやすい」を推奨理由から外した。
- 品質チェックリストの先頭に「第一印象」を追加した。Claude の評価が人間より一貫して高かったため。
- 実験方法に、要件ファイルの分離、IDE で開いたファイルの影響、点数の書き方を追加した。
