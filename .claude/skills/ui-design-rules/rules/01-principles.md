# 基本原則

## 目的

AIが生成するWeb UIにありがちな画一的なデザインを減らし、プロダクト固有の目的・ユーザー・情報構造に適した、意図のあるUIを効率よく作る。

## Rule 01：目的からレイアウトを決める

- 最初に画面の目的、対象ユーザー、主要な操作を整理する。
- 表示する情報とその優先順位を明確にする。
- 一般的なSaaSのテンプレートに情報を流し込むだけで画面を作らない。
- レイアウトは、情報の性質とユーザーのタスクに合わせて決定する。

## Rule 02：レイアウトの選択肢を広げる

- カードグリッド、テーブル、リスト、左右分割、非対称構成などから適切な構造を選ぶ。
- カード、中央寄せのヒーロー、均等幅の指標カードなどを無条件に採用しない。
- 複数案を作る場合は、配色だけでなく情報構造やレイアウトにも差をつける。
- 目新しさだけを目的に、分かりにくい構成を採用しない。

## Rule 03：タイポグラフィと余白に階層を持たせる

- 情報の重要度に応じて文字サイズ、太さ、行間、余白を使い分ける。
- すべての要素を同じ強さで表示しない。
- 画面を見たときに、重要な情報と次に行う操作が自然に分かるようにする。
- 余白は装飾ではなく、情報のグループ化と視認性のために使う。

## Rule 04：装飾には理由を求める

- グラデーション、ぼかし、影、過剰な角丸、装飾的なアイコンをデフォルトで追加しない。
- 装飾はブランド表現、状態の伝達、操作の明確化など、目的がある場合に使う。
- 装飾を追加する前に、装飾なしでも十分に情報が伝わるか検討する。
- 流行のスタイルを機械的に組み合わせない。

## Rule 05：プロダクト固有の特徴を反映する

- 業界、対象ユーザー、情報の性質、利用頻度、プロダクトの個性をデザインに反映する。
- サービス名を入れ替えるだけで成立するような汎用的な画面を避ける。
- 実際の用途に合う情報密度、ナビゲーション、操作方法を選ぶ。
- 要件が不明な場合は仮定を明示し、勝手に事実を作らない。
