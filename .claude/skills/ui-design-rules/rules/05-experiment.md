# 実験方法

ルール適用によって品質が上がり、修正時間が減ったかを検証する。

## 比較する2条件

同じ要件(同じデザインブリーフ)を2通りの方法で実装して比較する。

**Baseline**
普段どおりClaude Codeに画面を生成させる。このSkillのルールは使わない。

**Rules**
本ルールとデザイン案の比較プロトコル(`03-design-protocol.md`)を適用し、複数案から採用する。

## 条件をそろえる

結果の差がルール由来かどうかを見るため、以下をそろえる。

- 同じデザインブリーフを、そのまま両方に渡す。
- Baselineは**新しいセッション**で実行する(Rulesのやり取りを引きずらない)。
- 使うモデル、技術スタック、ビューポートを同じにする。
- Baselineのプロンプトは、ブリーフ本文と「この画面を作って」程度にとどめる。ルールの要素を混ぜない。
- 修正の指示は、どちらも「採用可能になるまで」同じ基準で出す。

## 記録する項目

`templates/experiment-log.md` に記録する。

- 初回生成にかかった時間
- 採用可能な画面になるまでの時間
- 見た目を修正した回数
- 機能やレイアウトの修正回数
- 生成案の間に明確な違いがあったか
- 最終的な画面品質
- 採用理由と却下理由

スクリーンショットと変更履歴を残す。保存先は `experiments/<実験ID>/screenshots/` を推奨する。

## 解釈の注意

- 1種類の画面だけで結論を出さない。複数の画面・プロジェクトで再現性を確認する。
- 時間はユーザーの待ち時間と手作業を含めて測る。Claudeの生成時間だけを見ない。
- 品質の評価は主観が入る。評価基準(`04-quality-checklist.md`)を先に決めておき、可能なら別の人にも見てもらう。
- Rulesは3案を作る分、初回生成は長くなりやすい。「採用可能になるまでの時間」と「修正回数」で比べる。
- 差が出なかった場合も、その結果を記録する。ルール改善の材料になる。
