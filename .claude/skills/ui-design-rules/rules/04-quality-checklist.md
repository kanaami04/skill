# 品質チェックリスト

生成した画面を以下の観点で確認する。
**チェックリストは機械的な合否判定ではなく、改善点を見つけるために使う。** 該当しない項目は理由を書いて飛ばしてよい。

上から順に確認する。**「第一印象」で問題があれば、下の項目が良くても採用可能にしない。** dashboard-001 では、要件を満たしていても、第一印象で2〜3点になった画面が多かった。

## 第一印象(最初の画面を一瞬見て)

- [ ] 画面の種類どおりに見える(例: 管理画面に見える。記事やニュースサイトに見えない)。
- [ ] 最初に目が行く場所が、決めた焦点と一致する。
- [ ] どこを見ればいいか迷わない(情報量が多すぎない)。
- [ ] 「AIが作った」と感じる要素がない(`02-anti-patterns.md` の AI典型が上限内)。

## 情報設計

- [ ] 画面の目的が明確である。
- [ ] 主要な情報が優先して見える。
- [ ] 主要な操作が理解しやすい。
- [ ] 実際の要件に不要な情報や、動かない飾りを追加していない。
- [ ] 同じ情報を2か所に出していない。
- [ ] 主役(一覧・本文・フォームなど)が画面の中心にあり、要件ごとの「お知らせ」の箱・数字の看板・自己説明の文・不要な区切りが主役を押しのけていない(`02-anti-patterns.md`「要件の写し方の典型」)。

## ビジュアル

- [ ] 強調が3段階以内で、焦点に集まっている。
- [ ] 文字サイズと太さに適切な階層がある。本文が小さすぎない。
- [ ] 囲みが意味の単位だけで、入れ子になっていない。
- [ ] 余白が情報のグループ化に役立っている。
- [ ] 色の使い方に一貫性があり、色だけで意味を伝えていない。
- [ ] プロダクト固有の特徴が表現されている(画面の種類の慣習の範囲内で)。

## 実装

- [ ] 主要な操作が機能する。
- [ ] レスポンシブ表示に大きな問題がない。
- [ ] 文字のはみ出しや横スクロールなどの不具合がない。
- [ ] アクセシビリティ上の基本的な問題がない(コントラスト、キーボード操作、フォーカス表示、ラベル)。
- [ ] 技術制約を守っている(単体HTML、外部依存なし)。
