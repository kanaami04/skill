#### 所見

**Baseline**

- 良い点
  - 共通データを正確に使っている。件数・日付・曜日はブリーフどおりで、データにない指標もない。
  - 機能要件1〜4がすべて動く。完了の切り替えで、件数・要約文・ナビの件数が連動する。
  - 冒頭の要約文(「今日対応するタスクは5件、注意が必要なプロジェクトは2件」)と「最優先」の印で、10秒テストの最初の2問には迷わず答えられる。
  - アクセシビリティが丁寧。スキップリンク、フォーカス表示、読み上げ用の通知がある。状態は記号＋文字、優先度はバー＋文字で表している。
- 気になる点
  - 紺のサイドバー＋白い角丸パネル＋色付きバッジという、典型的な SaaS の型。Northstar らしさはロゴの ✦ 程度で、サービス名を入れ替えても成立する。
  - 1行のタスクに、プロジェクト名・優先度バー・状態バッジ・メモが並ぶ。さらに状態色6色、行の左端の赤/橙の線、パネルの青い線が重なり、強調どうしが競合している。
  - 文字の強さの差が小さい。見出し 16px、タスク名 14px 太字、メタ情報 12px で、重要度の違いをバッジの色に頼っている。
  - 遅延・要注意のプロジェクトが、注意の欄とプロジェクト一覧の両方に、同じメモ付きで出る。
  - アクティビティが右の列の最下部にある。デスクトップでは最初の画面に入らず、モバイルではページ(約4100px)の末尾になる。10秒テストの3問目が △ なのはこのため。
  - 右の列が 360px と狭く、1440px でも「今後7日以内のタスク」の名前がほとんど2行に折り返す。
  - 「完了したタスク」の欄は必須ではない(悪くはないが、優先度の低い情報が優先度5より上にある)。
- 総合が4点の理由: 要件の満たし方と実装の質は高く、軽微な修正で採用できる水準。ただし改善の余地は主に「個性」と「強調の整理」で、これは軽微な修正では変わりにくい。

注意: A〜C の評価は、Baseline に対する人間の評価(線の二重、装飾の繰り返し、淡い色)を聞いたあとに付けた。その観点に引っ張られている可能性がある。

**A. Clarity First**

- 良い点
  - 読む順番が「今日 → 注意 → 一覧」と明快。見出し横の「5件」と内訳(期限切れ2 / ブロック中1 / 今日期限2)で、1問目に即答できる。
  - 淡い背景色の行やバッジはほぼなくなり、Baseline より色数が少ない。
  - 「昨日から 3件」が右の列の最初の画面に入っている。
- 気になる点
  - 骨格は Baseline とほぼ同じ(左ナビ + 白い本文 + 右の補助列、枠で囲んだ「今日」パネル)。サービス名を入れ替えても成立する。
  - **線の入れ子が残っている**: 「今日」パネルの上に太い紺の線があり、1行目の左にも紺の線がある。Baseline で人間が指摘した違和感と同じ種類。
  - 行内に枠付きのチップ(期限切れ・ブロック中・今日期限)と、右側の状態表示が並ぶ。T-103 は「ブロック中」チップと状態「ブロック」が重複する。
- 総合3点: Baseline よりは整理されているが、見た目の印象は大きくは変わらない。

**B. Editorial Character**

- 良い点
  - 3案で最も Baseline と違い、Northstar らしさがある(紙色の背景、明朝の見出し、朱色の一点、二重罫、大きな日付)。
  - 冒頭の一文で、1問目と2問目に答えられる。
  - 色の面を使わず、下線・黒い四角(優先度)・記号で区別している。淡い色のバッジの型から抜けている。
  - 注意プロジェクトに「自分の未完了タスク」(T-101、T-104 など)を添え、注意とタスクがつながっている。
- 気になる点
  - 縦に長い(1440幅で2,338px)。アクティビティとプロジェクト一覧は最初の画面の外。3問目は △。
  - 毎日何度も開く人には、大きな日付「15」と冒頭の一文が毎回同じ場所を占め、冗長になりうる。
  - 「紙色 + 明朝 + 朱色」は、最近の生成UIで「エディトリアル風」としてよく出る組み合わせでもある。SaaS 型のAIっぽさは避けているが、別の型に寄っている可能性がある。人間の第一印象で確かめたい。
- 総合4点: 個性と優先順位の両立は最も良い。縦の長さと、毎日使うときの冗長さが課題。

**C. Operational Density**

- 良い点
  - 1440×900 で、ほぼ全領域が1画面に入る。私の環境ではページ高 923px で、プロジェクト表の最終行がわずかに切れた。Rules セッションの報告(900px、スクロールなし)とは少し差があり、スクロールバーの幅の分だけ折り返しが増えた可能性がある。
  - 全タスクを1表にまとめ、「今日対応」と「今後7日」をグループの見出しで分けている。列で見比べられる。
  - プロジェクト表が深刻な順で、状態メモが同じ行にある。注意の欄を別に作らず、重複がない。
  - 優先度は ▲高 / ■中 / ▽低 の形と文字。色の面はほぼ使っていない。
- 気になる点
  - 本文13pxで、初見では読みにくい。
  - タスク行とプロジェクト行の左端の赤や琥珀の線は残っている(入れ子ではない)。
  - 見た目は一般的な業務ツールで、Northstar らしさは弱い。
- 総合4点: 想定ユーザー(毎日数回、短時間)には最も合う。AIっぽさは、SaaS テンプレートというより業務ツール寄りで、Baseline より弱い。

**Rules セッションの推奨(A)について**

Rules セッションは A を推奨したが、私は C(次点 B)を推す。A は3案の中で最も Baseline に近く、人間が Baseline で指摘した線の入れ子も残っているため。Rules のプロトコルでは「仕様化しやすさ」が推奨理由に入りやすく、無難な案が選ばれやすい可能性がある(ルール改善の候補)。

- ルールに追加・変更したいこと(候補。この実験が終わるまでルールには反映しない):
  - 左のアクセント線を既定にしない: 4画面すべてで、パネル・行・メモの左に線を付けていた(CSS上の左線・内側の影による線: Baseline 6、A 6、B 1、C 14)。線は「一覧の中で特定の行だけを目立たせる」など、目的がある1か所に限る。(人間評価より)
  - 方向性 B「Editorial Character」の定義の見直し: 「エディトリアル」が記事・ニュースサイトの見た目を誘導した。個性は、プロダクトの種類(管理アプリ)の慣習の範囲内で出す。名前も「Brand Character」などに変える案。
  - 情報密度を上げる案(C)でも、最初に見るべき1点(焦点)を作る。密度が高いほど、注目点がないと「どこを見ればいいか分からない」になる。
  - A のように Baseline と同じ骨格になった案は、3案の1つとして価値が低い。「普段どおり作った場合と何が違うか」を各案で説明させる。
  - 強調の入れ子を避ける: 親(パネル)と子(行)の両方にアクセント線や色を付けない。強調はどちらか一方に。(Baseline の人間評価より)
  - 淡い色の面(薄い背景のバッジ・行)を既定にしない: 薄い背景＋濃い文字のバッジを全状態に使うと、すべてが同じ強さになる。色は意味がある箇所に絞る。
  - 個別に良い要素でも、全行に繰り返すと見づらくなる。繰り返す装飾の量に上限を考える。
  - Claude の評価方法: チェックリストでは第一印象の「AI臭」が点数に出にくい。第一印象の評価を独立した項目にする。
