# 画面要件 — Parcel のサービス紹介ページ(LP)

## 基本情報

- 画面名: サービス紹介ページ(LP)
- プロダクト名 / 業界: Parcel(架空の EC 注文管理サービス)
- 画面の種類: LP(ランディングページ)
- 作成日: 2026-10-15

## 依頼

架空の EC 注文管理サービス「Parcel」の、サービス紹介ページ(LP)をデザインしてください。

検索や紹介でこのページに来た小さなネットショップの運営者が、Parcel が何をしてくれるサービスかを理解し、無料で使い始める(アカウントを作る)ところまでを想定してください。

## 画面の目的

訪問者が、次の流れで無料登録まで進めるようにする。

1. Parcel が何のサービスで、自分のためのものだと分かる。
2. 自分の困りごとが解決しそうだと思える。
3. 料金と始め方が分かり、不安(勝手に課金されないか、など)が解消される。
4. 無料登録のフォームに入力して送る。

このページを開いて10秒以内に、次の質問に答えられることを目標にする。

- 何のサービスで、誰のためのものか。
- 何が一番うれしいのか。
- 次に何をすればよいか(どこから始められるか)。

## 対象ユーザー(訪問者)

- **誰か**: 個人〜スタッフ数名で、ネットショップを運営している人。商品づくりや仕入れもしながら、注文対応・入金確認・発送を少人数で回している。
- **今のやり方**: ネットショップ作成サービスの管理画面、メール、表計算ソフトを行き来して注文を管理している。
- **来るきっかけ**: 「注文管理 小規模」などで検索、または知人の紹介。
- **利用環境**: スマートフォンとデスクトップが半々。スマートフォンで見て、あとでデスクトップで登録することもある。
- **知識**: ネットショップの運営には慣れている。専門用語の多い説明は好まない。

## 伝えること(ページに載せてよい事実)

**このページに載せる事実は、以下だけ。** ここにない数字(導入社数、満足度、削減時間など)、実在の会社名・ロゴ、ここにない利用者の声は作らない。見出しや本文の言い回しは、以下の事実から自由に書いてよい。

### Parcel とは

- 小さなネットショップが、今日やるべき注文対応を取りこぼさないための注文管理サービス。
- 大規模な EC 向けの多機能さより、少人数での毎日の運営のしやすさを重視している。

### 運営者の困りごと(Parcel が解決するもの)

- 新しい注文の確認漏れ。
- 銀行振込・コンビニ払いの入金確認の手間。支払期限が過ぎた注文に気づかない。
- 発送期限の管理。期限を過ぎてから気づく。
- 外出先で、スマートフォンから注文状況を確認しづらい。

### 機能

| 機能 | 内容 |
|---|---|
| 要対応の注文を自動で抽出 | 新規の注文、決済エラー、今日が発送期限・期限超過の注文、今日が支払期限の未入金の注文を、理由と次にやることつきで一覧にする |
| まとめて発送準備 | 発送できる注文だけを選んで、まとめて「発送準備中」にする。発送できない注文が混ざっていれば理由を表示する |
| 支払い状態と注文状態を一覧で | 入金済み・未入金・決済エラー・代引きなどの支払い状態と、注文状態を、1つの一覧で確認できる |
| スマートフォン対応 | 外出先でも、要対応の注文と注文の詳細を確認できる |
| 注文データの取り込み | CSV ファイルで取り込める。主要なネットショップ作成サービスとの連携にも対応(サービス名は載せない) |

### 始め方(3ステップ)

1. メールアドレスとショップ名でアカウントを作る(1分ほど)。
2. 注文データを CSV で取り込むか、ネットショップ作成サービスと連携する。
3. 「要対応」の一覧で、今日やることを確認する。

|---|---|---|---|---|---|
| フリー | ¥0 | ¥0 | 月30件 | 1人 | |
| スタンダード | ¥2,980 / 月 | ¥29,800 / 年 | 月500件 | 3人 | |
| プロ | ¥6,980 / 月 | ¥69,800 / 年 | 月3,000件 | 10人 | 優先サポート(メールの返信は1営業日以内) |

| 質問 | 回答 |
|---|---|
| 無料期間が終わると、自動で課金されますか? | いいえ。有料プランを自分で選ぶまで課金されません。無料期間が終わると、フリープランに切り替わります。 |
| いつでも解約できますか? | はい。設定画面からいつでも解約できます。解約の手数料はありません。 |
| 注文データはどうやって取り込みますか? | CSV ファイルを取り込むか、ネットショップ作成サービスと連携します。手順は登録後の画面で案内します。 |

| フリープランで注文が30件を超えたらどうなりますか? | 31件目以降の注文は、翌月まで取り込めません。有料プランに切り替えると、すぐに取り込めます。 |

## 主要な操作

重要な順。

1. 「無料で始める」から、登録フォームに入力して送る。
2. 料金を確認する(月払い / 年払いの切り替え)。
3. よくある質問を開いて読む。

## 必須コンテンツと、置いてはいけないもの

- **必須**
  - ヘッダー: ロゴ(文字でよい)、ページ内リンク(機能、料金、よくある質問)、「無料で始める」ボタン。
  - 最初の画面: 何のサービスか、誰のためのものか、「無料で始める」ボタン。
  - 困りごと、機能、始め方、料金、利用者の声、よくある質問、登録フォーム、フッター。
  - 製品の画面のイメージ: Parcel の「要対応」の一覧を、HTML と CSS で簡単に描いたもの(画像は使わない)。描く場合の注文データは、下の「画面イメージ用のデータ」を使う。
- **置いてはいけないもの**
  - 上の「伝えること」にない数字・実績・会社名・ロゴ・利用者の声。
  - 動かない要素(押しても何も起きない「デモを見る」ボタンなど)。ページ内リンクと、下の機能要件にある操作だけにする。

## 機能要件(全案共通)

Vanilla JavaScript で以下を動かす。通信はしない。

1. **ページ内の移動**: ヘッダーのリンクと「無料で始める」ボタンで、該当の位置に移動する。
2. **料金の切り替え**: 「月払い」「年払い」を切り替えると、料金表の金額が変わる。
3. **よくある質問の開閉**: 質問ごとに回答を開閉できる。キーボードでも操作できる。
4. **登録フォーム**: 入力項目は、メールアドレス、ショップ名、利用規約への同意(チェックボックス)。
   - 送信時に入力を確認する。メールアドレスの形式、ショップ名の未入力、同意の未チェックのそれぞれで、項目のそばにエラーを出す。
   - すべて正しければ、フォームの代わりに完了の表示(「確認メールを送りました」に相当する内容と、入力したメールアドレス)を出す。
5. **モバイルのナビゲーション**: 狭い画面ではヘッダーのリンクを折りたたみ、ボタンで開閉できる。

## 技術制約

- HTMLファイル1つ。ブラウザでファイルを直接開いて表示できること(`file://`)。
- CSSはHTML内の `<style>` に書く。JavaScriptは必要な場合だけ、Vanilla JSでHTML内の `<script>` に書く。
- ビルドツール、フレームワーク、外部UIライブラリは使わない。
- 外部フォント、外部画像、CDNなどのネットワーク依存を避ける。フォントはシステムフォントを使う。アイコンが必要ならインラインSVGか文字で表す。
- 基本的なアクセシビリティを満たす: コントラスト、キーボード操作、フォーカス表示、操作要素とフォーム項目のラベル。
- 本実装の技術スタック: 未定。
